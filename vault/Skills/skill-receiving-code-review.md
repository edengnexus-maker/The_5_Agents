# Skill: receiving-code-review

## מה הסקיל עושה

**קבלת ביקורת קוד בצורה נכונה** — דורש הערכה טכנית אמיתית, לא הסכמה מתוך נימוס.

### עיקרון הליבה

> "בדוק לפני יישום. שאל לפני הנחה. נכונות טכנית מעל נוחות חברתית."

### תבנית תגובה

1. **קרא**: feedback מלא ללא תגובה רגשית
2. **הבן**: נסח מחדש את הדרישה במילים שלך (או שאל)
3. **אמת**: בדוק מול מציאות ה-codebase
4. **הערך**: האם נכון טכנית *לcodebase הזה*?
5. **הגב**: אישור טכני או דחייה מנומקת
6. **יישם**: פריט אחד בכל פעם, בדוק כל אחד

### תגובות אסורות

- "אתה לגמרי צודק!" — חריגה מפורשת
- "כמובן!" ויישום עיוור
- "זה מורכב" בלי הסבר
